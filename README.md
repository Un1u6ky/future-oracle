# Future Oracle — Crypto Pulse

Учебный прототип «предсказателя будущего»: **направление цены криптоактива на 24 часа**.

Это не торговый бот и не обещание доходности. Реальные деньги не подключаются. Прогноз — детерминированный score по сохранённым таблицам, его можно пересчитать вручную.

## Как запустить

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app          # http://127.0.0.1:8000
```

В репозитории уже лежит `data/oracle.db` со снятыми 14.08.2026 котировками, Fear & Greed и новостями. Интерфейс открывается сразу.

Полезные команды:

```bash
python -m app ingest      # заново сходить в API (нужен интернет)
python -m app recompute   # пересчитать прогнозы только из SQLite
pytest                    # арифметика карточки зафиксирована тестами
```

## Какие данные взяли

Прогноз по 10 монетам: BTC, ETH, SOL, BNB, XRP, DOGE, ADA, AVAX, LINK, TON.

| Источник | Что даёт | Таблица |
|---|---|---|
| [CoinGecko Markets + chart](https://api.coingecko.com/api/v3/coins/markets) | цена, Δ24ч, Δ7д, объём, high/low, 8 дней истории | `market_snapshots`, `raw_records` |
| [Alternative.me Fear & Greed](https://api.alternative.me/fng/) | дневной индекс 0–100 | `fear_greed` |
| [Cointelegraph RSS](https://cointelegraph.com/rss) | заголовки, время, ссылка | `news_items`, `news_mentions` |

Сырой JSON/RSS пишется в `raw_records` до нормализации. История обновлений прогноза — в `forecast_updates`.

## Как устроена база

SQLite, файл `data/oracle.db`:

- `sources` — справочник источников и статус последнего fetch
- `raw_records` — сырой payload
- `assets` — тикер, CoinGecko id, ключевые слова
- `market_snapshots` — нормализованный рынок (live и дневная история)
- `fear_greed` — индекс по дням
- `news_items` + `news_mentions` — заголовок, лексикон-сентимент, связь с активом
- `indicators` — пять сигналов, score, согласие, покрытие новостей
- `forecasts` — направление, P(рост), уверенность, риск, аргументы, used_data, факт и Brier
- `ingest_runs` — журнал прогонов

Схема создаётся в `app/models.py`. Прогноз **не генерируется в шаблоне**: карточка читает `forecasts` + `indicators`.

## Как работает алгоритм

Все сигналы ∈ [−1; +1]. Веса фиксированы и в сумме дают 1:

```
score = 0.28·momentum + 0.18·volume + 0.12·range + 0.25·news + 0.17·fear_greed

momentum = 0.65·clip(Δ24h / 15) + 0.35·clip(Δ7d / 25)
volume   = sign(momentum) · max(tanh(volume_ratio − 1), 0)
range    = clip((0.5 − position_in_24h_range) · 2)     # mean reversion
news     = Σ decay·weight·lexicon / Σ decay·weight     # полураспад 18ч
f&g      = (50 − value) / 50                           # контрарий

P(рост)     = 1 / (1 + e^(−3.2 · score))
direction   = up если score > 0.12, down если < −0.12, иначе sideways
confidence  = 100 · (0.50·|score| + 0.32·agreement + 0.18·news_coverage)
              × 0.85, если внутридневной диапазон > 8%
```

Уверенность ≠ вероятность. P(рост) — оценка направления. Уверенность — насколько сигналы согласованы и хватает ли новостей.

Риск собирается правилами из тех же полей: конфликт знаков, узкий score, пустые новости, широкий диапазон, тонкий объём.

Лексикон заголовков — фиксированный список фраз в `app/scoring/lexicon.py`. LLM в скоринг не входит.

Тест `tests/test_scoring.py::test_worked_example_numbers_add_up` ломается, если карточка начнёт врать.

## Какие цифры должны сходиться

Пример живого BTC на снимке 14.08.2026 09:54 UTC, цена **$62 751**:

| Сигнал | Сырые данные | Норм. | Вес | Вклад |
|---|---|---|---|---|
| momentum | Δ24ч −1.50%, Δ7д −2.20% | −0.096 | 0.28 | −0.0268 |
| volume | 0.65× среднего | 0.000 | 0.18 | 0.0000 |
| range | цена на 8% диапазона ($62 648–$63 918) | +0.838 | 0.12 | +0.1005 |
| news | 6 заголовков, лексикон не сработал | 0.000 | 0.25 | 0.0000 |
| fear_greed | 29 Fear | +0.420 | 0.17 | +0.0714 |
| **score** | | | | **+0.1451** |

Проверка: −0.0268 + 0 + 0.1005 + 0 + 0.0714 = **+0.1451**.

- score +0.145 > 0.12 → **рост**
- P(рост) = 1/(1+e^(−3.2·0.1451)) = **61.4%**
- согласие 3/4 ненулевых сигналов (range и F&G за рост, momentum против) = 0.75
- уверенность = 100·(0.50·0.145 + 0.32·0.75 + 0.18·1.0) = **46.6%**
- риск средний: импульс против знака, объём тонкий

Итог карточки не «монета вырастет», а «mean-reversion от низа диапазона плюс страх рынка перевесили слабый минус за сутки; новости нейтральны, объём ход не подтверждает».

## Как система понимает, что ошиблась

У прогноза есть `price_at_forecast` и `resolve_after = as_of + 24h`.

Когда появляется более поздний снимок:

```
return = (price_later / price_then − 1) · 100
actual = up если return > +0.5, down если < −0.5, иначе sideways
was_correct = (direction == actual)
brier = (P(рост) − target)²     # target 1 / 0 / 0.5
```

Живые 24 часа на первом запуске ещё не прошли — поэтому те же формулы прогоняются как **бэктест** по дневным свечам CoinGecko за 6 дней. Новости берутся только с `published_at <= as_of`.

На этом окне (падающий рынок):

- модель: **14 / 60 = 23%** верных направлений
- наивный baseline «всегда down»: **47%**
- Brier ≈ **0.20**

Это не прячется. Модель часто ставит `sideways` или контрарный `up`, а факт был `down`. Страница «Ошибки» показывает каждую строку. Короткий бэктест легко врёт — для задания важнее, что ошибка **измерима из тех же таблиц**.

## Что использовали из AI

- Cursor (Grok) — каркас приложения, UI, формулировки README.
- Скоринг, лексикон и разрешение прогноза — обычный Python, без вызова модели.
- GLM / внешние LLM в рантайме не используются: иначе цифры на карточке нельзя было бы свести в таблице.
